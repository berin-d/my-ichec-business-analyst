TP 2 : Formulaires et Base de Données

Contexte

Votre application affiche des données statiques codées en dur dans Python. Dans ce TP, vous allez permettre aux utilisateurs d'ajouter leurs propres demandes via un formulaire. Pour que ces données ne soient pas perdues à chaque redémarrage du serveur, vous connecterez ensuite votre application à une base de données SQLite avec l'ORM SQLAlchemy, et vous implémenterez le cycle CRUD complet (Create, Read, Update, Delete).

Objectifs

  1. Créer un formulaire HTML et gérer sa soumission en POST.
  2. Valider les données côté serveur et informer l'utilisateur via des "Flash Messages".
  3. Installer et configurer Flask-SQLAlchemy.
  4. Modéliser la donnée FeatureRequest avec horodatage.
  5. Implémenter le cycle CRUD complet (Créer, Lire, Modifier, Supprimer).
  6. Gérer l'upload de fichiers de manière sécurisée.

Exercice 1 : Le Formulaire d'Ajout, Validation et Messages Flash

Tâche : Créez une page avec un formulaire, validez les données soumises côté serveur et informez l'utilisateur du résultat.

Instructions :

  1. Ajoutez un bouton "Ajouter une demande" sur index.html.
  2. Créez une nouvelle route /feature/add acceptant les méthodes ['GET', 'POST'].
  3. En GET : Retournez un template add_feature.html contenant un <form method="POST"> avec les champs : Titre, Description (textarea), Nature (liste déroulante : Feature, Bug, Amélioration) et Priorité (Haute, Moyenne, Basse).
  4. En POST (request.method == 'POST') :
    • Récupérez les données avec request.form.get().
    • Validez les données : vérifiez que le titre n'est pas vide et qu'il ne dépasse pas 100 caractères. Si la validation échoue, affichez un message d'erreur avec flash("...", "danger") et ré-affichez le formulaire.
    • Si tout est valide, affichez temporairement les données dans la console avec un print().
    • Lancez un message de succès : flash("Demande ajoutée !", "success"). (Nécessite une SECRET_KEY dans app.py !)
    • Redirigez vers l'accueil (redirect(url_for('index'))).
  5. Dans base.html, ajoutez le code nécessaire pour afficher les messages flash sous forme d'alertes Bootstrap (avec la classe correspondant à la catégorie : success, danger, warning...).

Pattern Post-Redirect-Get (PRG) : Remarquez que lors d'un POST réussi, on ne retourne pas directement un template — on redirige vers une autre page. Cela empêche l'utilisateur de re-soumettre le formulaire s'il rafraîchit la page. C'est un pattern standard du développement web.

Exercice 2 : Configuration de la Base de Données et Modèle

Tâche : Préparer la base locale pour stocker de façon pérenne les demandes.

Instructions :

  1. Installez flask-sqlalchemy dans votre environnement. Mettez à jour votre requirements.txt.
  2. Dans app.py, configurez app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///featurehub.db' et initialisez db = SQLAlchemy(app).
  3. Créez une classe FeatureRequest héritant de db.Model avec :
    • id : Integer, Primary Key.
    • title : String(100), non vide.
    • description : Text.
    • status : String, défaut "En attente".
    • nature : String, défaut "Feature".
    • priority : String, défaut "Moyenne".
    • created_at : DateTime, avec une valeur par défaut automatique.
    • Ajoutez un attribut __tablename__ = 'feature_requests' pour nommer explicitement la table.
    • Ajoutez une méthode __repr__ pour faciliter le débogage (ex: <FeatureRequest 1: Dark Mode>).

Astuce pour le champ created_at :

from datetime import datetime

class FeatureRequest(db.Model):
    __tablename__ = 'feature_requests'

    # ... colonnes ...
    created_at = db.Column(db.DateTime, default=datetime.utcnow)

    def __repr__(self):
        return f'<FeatureRequest {self.id}: {self.title}>'
  1. Pour créer le fichier .db au démarrage, appelez db.create_all() dans un bloc de contexte d'application.

Vérification SQL : Après la création de la base, vous pouvez inspecter la structure générée par l'ORM en ouvrant le fichier .db avec le CLI sqlite3 :

sqlite3 instance/featurehub.db .tables .schema feature_requests

Comparez le CREATE TABLE généré avec la définition de votre modèle Python.

Exercice 3 : Persistance des Données (Création & Lecture)

Tâche : Lier votre formulaire à la base de données et afficher les données persistées.

Instructions :

  1. Route Add (Écriture) :
    • Dans votre bloc POST, remplacez le print en instanciant un nouvel objet FeatureRequest avec les données reçues.
    • Ajoutez-le à la session : db.session.add(votre_objet).
    • Sauvegardez en protégeant la transaction :
try:
    db.session.add(votre_objet)
    db.session.commit()
    flash("Demande ajoutée !", "success")
except Exception:
    db.session.rollback()
    flash("Erreur lors de l'enregistrement.", "danger")
  1. Route Index (Lecture) :
    • Supprimez vos fausses données en dur.
    • Récupérez toutes les demandes de la base, triées par date de création décroissante (les plus récentes en premier) :
features = FeatureRequest.query.order_by(FeatureRequest.created_at.desc()).all()
  1. Gestion de la liste vide : Dans index.html, si la liste de features est vide, affichez un message invitant l'utilisateur à créer sa première demande (avec un lien vers le formulaire d'ajout) au lieu d'afficher une page vide.
  2. Affichage de la date : Sur chaque carte, affichez la date de création formatée.

Astuce : Jinja2 permet d'utiliser le filtre strftime sur un objet datetime :

{{ feature.created_at.strftime('%d/%m/%Y à %H:%M') }}

Vérification : Ajoutez une demande via le formulaire, puis redémarrez votre serveur. La demande doit persister !

Exercice 4 : Page de Détails

Tâche : Créer une page dédiée à l'affichage complet d'une seule demande via son ID.

Instructions :

  1. Créez une route /feature/<int:id>. Ce paramètre dynamique id vous permet d'identifier quelle demande afficher.
  2. Dans la fonction, requêtez la demande correspondante avec SQLAlchemy (FeatureRequest.query.get_or_404(id)).
  3. Passez cet objet à un nouveau template view_feature.html qui affiche tous les champs de la demande (titre, description, statut, nature, priorité, date de création).
  4. Dans index.html, transformez le titre de chaque carte en un lien dirigeant vers la page de détails de la carte en question.

Exercice 5 : Modification d'une Demande (Update)

Tâche : Permettre de modifier une demande existante via un formulaire pré-rempli.

Instructions :

  1. Créez une route /feature/<int:id>/edit acceptant les méthodes ['GET', 'POST'].
  2. Récupérez la demande par son ID (get_or_404).
  3. En GET : Affichez un template edit_feature.html contenant un formulaire pré-rempli avec les valeurs actuelles de la demande (attribut value pour les champs texte, selected pour les listes déroulantes).
  4. En POST :
    • Récupérez les nouvelles valeurs du formulaire.
    • Appliquez la même validation que dans l'exercice 1 (titre requis, longueur max).
    • Mettez à jour les attributs de l'objet existant (pas besoin de db.session.add(), l'objet est déjà suivi par SQLAlchemy).
    • Sauvegardez avec db.session.commit().
    • Redirigez vers la page de détails de la demande.
  5. Ajoutez un bouton "Modifier" sur la page de détails (view_feature.html) qui mène vers cette route.

Astuce : Vous pouvez réutiliser une grande partie du HTML du formulaire d'ajout. Si vous voulez factoriser, créez un template partiel _form.html inclus par add_feature.html et edit_feature.html.

Exercice 6 : Suppression d'une Demande (Delete)

Tâche : Permettre de supprimer une demande existante, avec une confirmation pour éviter les suppressions accidentelles.

Instructions :

  1. Créez une route /feature/<int:id>/delete acceptant uniquement la méthode POST.
  2. Récupérez la demande par son ID, supprimez-la (db.session.delete(feature)) et sauvegardez (db.session.commit()).
  3. Affichez un message flash de confirmation et redirigez vers l'accueil.
  4. Sur la page de détails, ajoutez un bouton "Supprimer" dans un petit formulaire <form method="POST"> pointant vers la route de suppression.

Pourquoi POST et pas GET ? Une requête GET ne doit jamais modifier des données. Un simple lien <a href="/feature/1/delete"> pourrait être suivi par un robot d'indexation ou par un pré-chargement du navigateur, ce qui supprimerait des données involontairement. En utilisant POST, on s'assure que la suppression est une action intentionnelle.

Challenge optionnel : ajoutez une modale Bootstrap de confirmation ("Êtes-vous sûr ?") qui s'affiche au clic sur le bouton Supprimer, avant de soumettre le formulaire.

Exercice 7 : Upload de Fichiers (Pièces Jointes)

Tâche : Permettre à l'utilisateur de joindre une image ou un document (spécification technique, capture d'écran du bug) à sa demande, de manière sécurisée.

Instructions :

  1. Modèle : Ajoutez une colonne filename (String, nullable) à votre modèle FeatureRequest. Recréez la base de données (supprimez le fichier .db et relancez).
  2. Configuration : Dans app.py, configurez le dossier de destination, la taille maximale autorisée et les extensions acceptées :
app.config['UPLOAD_FOLDER'] = 'static/uploads'
app.config['MAX_CONTENT_LENGTH'] = 2 * 1024 * 1024  # 2 Mo max
ALLOWED_EXTENSIONS = {'png', 'jpg', 'jpeg', 'gif', 'pdf'}

def allowed_file(filename):
    return '.' in filename and filename.rsplit('.', 1)[1].lower() in ALLOWED_EXTENSIONS

Assurez-vous que le dossier static/uploads existe.

  1. HTML :
    • Modifiez le formulaire dans add_feature.html pour supporter l'envoi de fichiers : ajoutez l'attribut enctype="multipart/form-data" à la balise <form>.
    • Ajoutez un champ <input type="file" name="file" class="form-control">.
  2. Backend (Route Add) :
    • Lors de la soumission en POST, récupérez le fichier avec file = request.files.get('file').
    • Si un fichier est présent et qu'il a un nom, vérifiez que son extension est autorisée avec allowed_file(). Si l'extension n'est pas autorisée, affichez un message flash d'erreur.
    • Si le fichier est valide, sécurisez son nom (from werkzeug.utils import secure_filename) et sauvegardez-le dans app.config['UPLOAD_FOLDER'].
    • Enregistrez le nom du fichier dans l'objet FeatureRequest avant le db.session.commit().
  3. Affichage : Dans la page de détails (view_feature.html), si la demande possède un filename :
    • S'il s'agit d'une image (png, jpg, gif), affichez-la directement avec une balise <img>.
    • Sinon, affichez un lien de téléchargement.
