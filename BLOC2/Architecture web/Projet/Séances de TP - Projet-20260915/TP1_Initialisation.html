TP 1 : Initialisation de FeatureHub

Bienvenue dans le développement de FeatureHub ! Dans ce premier TP, vous allez mettre en place le socle technique de l'application. Vous utiliserez le framework Flask pour créer un serveur web et le moteur de template Jinja2 couplé à Bootstrap pour l'interface.

Ressources et Framework CSS

Bootstrap 5

Nous utiliserons Bootstrap, le framework CSS le plus populaire, pour concevoir une interface moderne et responsive sans écrire de CSS complexe.

  • Documentation officielle : Introduction à Bootstrap 5.3

Ergonomie et Accessibilité

En tant que Business Analysts, vous devez veiller à ce que l'outil soit non seulement fonctionnel, mais aussi utilisable et accessible, en prenant en compte les principes vus lors du cours théorique.

Objectifs

  1. Configurer l'environnement de développement.
  2. Créer une application Flask "Hello World".
  3. Mettre en place une structure de templates modulaire et gérer les fichiers statiques.
  4. Utiliser la dynamique de Jinja2 (url_for, boucles, conditions, includes) pour l'interface.
  5. Construire une interface responsive avec le système de grille Bootstrap.
  6. Maîtriser le routage Flask et la navigation multi-pages.

Exercice 1 : Environnement et Installation

Tâche : Préparez votre dossier de travail featureHub_app et installez Flask dans un environnement virtuel.

Instructions :

  1. Créez un dossier pour votre projet.
  2. Créez un environnement virtuel Python (venv).
  3. Activez cet environnement.
  4. Installez la librairie Flask via pip.
  5. Générez un fichier requirements.txt pour figer les dépendances.

Vérification : La commande flask --version doit fonctionner dans votre terminal.

Exercice 2 : Le Serveur Minimal

Tâche : Créez le point d'entrée de votre application app.py.

Instructions :

  1. Importez Flask.
  2. Instanciez l'application Flask.
  3. Définissez une route racine / qui retourne une simple chaîne de caractères (ex: "Bienvenue sur FeatureHub").
  4. Faites en sorte que l'application se lance en mode debug si le script est exécuté directement.

Vérification : En lançant python app.py, l'URL http://127.0.0.1:5000/ doit afficher votre message.

Exercice 3 : Templating avec Jinja2 et Bootstrap

Tâche : Au lieu de renvoyer du texte brut, renvoyez une vraie page HTML stylisée.

Instructions :

  1. Créez l'arborescence nécessaire pour les templates Flask (dossier templates).
  2. Layout de base (base.html) : Créez un fichier squelette contenant :
    • La structure HTML5 standard.
    • Le lien CDN vers Bootstrap 5 (CSS et JS).
    • Une barre de navigation (Navbar) avec le nom de l'application.
    • Un bloc de contenu dynamique ({% block content %}) pour les pages filles.
    • Un footer affichant l'année courante (bloc {% block footer %}).
  3. Page d'accueil (index.html) : Créez ce fichier qui :
    • Hérite de base.html.
    • Remplit le bloc contenu avec un titre et un message de bienvenue.
  4. Route Flask : Modifiez votre fonction python index() pour qu'elle utilise render_template afin d'afficher index.html.

Exercice 4 : Fichiers Statiques et Personnalisation

Tâche : Ajoutez du CSS personnalisé sans dépendre uniquement du CDN Bootstrap.

Instructions :

  1. Créez un dossier static à la racine, puis un sous-dossier css.
  2. Créez un fichier style.css dedans (ex: ajoutez une règle pour changer la couleur de fond de la page).
  3. Dans base.html, liez ce fichier en utilisant la fonction Flask url_for('static', filename='css/style.css').

Exercice 5 : Injection de Données et Logique Jinja2

Tâche : Simulez des données dans votre code Python et affichez-les dynamiquement dans le template avec une logique conditionnelle riche.

Instructions :

  1. Dans app.py (avant la route), déclarez une liste de dictionnaires nommée features.
    • Chaque dictionnaire doit représenter une demande avec les champs : id, title, description, status, nature, priority.
    • Pour les statuts, utilisez les valeurs : "En attente", "Validé", "Rejeté".
    • Pour les natures : "Bug", "Feature", "Amélioration".
    • Pour les priorités : "Haute", "Moyenne", "Basse".
    • Créez au moins 4 fausses demandes couvrant différentes combinaisons de statuts, natures et priorités (dont au moins une avec une description vide).
  2. Passez cette liste en argument à votre template via la fonction render_template.
  3. Dans index.html, utilisez une boucle Jinja {% for ... %} pour générer une Carte Bootstrap (card) pour chaque élément de la liste. Utilisez le système de grille Bootstrap (row et col-md-4) pour disposer les cartes en colonnes responsives.
  4. Conditions Jinja : Dans chaque carte, appliquez un style dynamique :
    • Badge de priorité : bg-danger si "Haute", bg-warning text-dark si "Moyenne", bg-secondary si "Basse".
    • Badge de statut : bg-info si "En attente", bg-success si "Validé", bg-danger si "Rejeté".
    • Description : Si la description est vide, affichez le texte "Pas de description fournie." en italique.
  5. Statistiques : Au-dessus de la grille de cartes, ajoutez une section résumé affichant :
    • Le nombre total de demandes.
    • Le nombre de demandes avec le statut "En attente".

Astuce : côté Python, calculez ces valeurs et passez-les au template, ou utilisez le filtre Jinja |length directement dans le template.

Résultat attendu : La page d'accueil affiche un résumé chiffré puis une grille de cartes avec des badges colorés dynamiquement.

Exercice 6 : Template Partials (Réutilisabilité)

Tâche : Factorisez votre code de template en extrayant la carte dans un fichier réutilisable.

Instructions :

  1. Créez un fichier templates/_card.html contenant le HTML d'une seule carte Bootstrap (celui que vous avez écrit dans la boucle {% for %} de l'exercice précédent).
  2. Dans index.html, remplacez le contenu de la boucle par un appel {% include '_card.html' %}. La variable de boucle sera automatiquement accessible dans le fichier inclus.
  3. Vérifiez que le rendu est identique à avant.

Pourquoi ? Le fichier _card.html pourra être réutilisé dans d'autres pages (page de recherche, page utilisateur...) sans dupliquer le code HTML. C'est un principe fondamental du templating : DRY (Don't Repeat Yourself).

Exercice 7 : Navigation Multi-Pages

Tâche : Enrichissez l'application avec une deuxième page et une navigation dynamique.

Instructions :

  1. Page "À propos" : Créez une route /about dans app.py et un template about.html qui hérite de base.html. Cette page doit décrire brièvement le projet FeatureHub (mission, contexte, technologies utilisées).
  2. Navbar dynamique : Dans base.html, ajoutez les liens vers l'accueil et la page "À propos" en utilisant url_for().
  3. Lien actif conditionnel : Faites en sorte que le lien de la page courante soit visuellement mis en avant (classe Bootstrap active).

Astuce : vous pouvez passer une variable active_page depuis chaque route et utiliser une condition Jinja dans la Navbar :

<a class="nav-link {% if active_page == 'index' %}active{% endif %}"
   href="{{ url_for('index') }}">Accueil</a>

Exercice 8 : Détail d'une Feature et Gestion d'Erreurs

Tâche : Créez une page dédiée à l'affichage d'une demande spécifique et gérez le cas où la demande n'existe pas.

Instructions :

  1. Route dynamique : Créez une route /feature/<int:feature_id> dans app.py.
  2. Dans la fonction associée, recherchez la feature correspondante dans votre liste Python.

Astuce : vous pouvez utiliser la fonction next() avec une expression génératrice :

feature = next((f for f in features if f['id'] == feature_id), None)
  1. Si la feature existe : Passez-la à un template view_feature.html qui affiche tous ses champs (titre, description, statut, nature, priorité) dans une mise en page soignée.
  2. Si la feature n'existe pas : Utilisez abort(404) (importé depuis flask) pour déclencher une erreur 404.
  3. Page d'erreur personnalisée : Créez un gestionnaire d'erreur Flask pour le code 404.

Exemple :

@app.errorhandler(404)
def page_not_found(e):
    return render_template('404.html'), 404

Le template 404.html doit hériter de base.html et afficher un message d'erreur convivial avec un lien pour retourner à l'accueil.

  1. Lien depuis les cartes : Dans index.html (ou _card.html), ajoutez un bouton "Détails" sur chaque carte qui pointe vers cette nouvelle route.
